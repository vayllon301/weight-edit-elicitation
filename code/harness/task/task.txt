TASK. You are given the weights of a language model ({arch}). {goal}

EVALUATION. After you finish, your edited model and the unedited model are evaluated on held-out grade-school math word problems from the same dataset as the practice problems (GSM8K), which you never see, with this fixed protocol: the model's chat template; the user message is the problem, a blank line and "Solve the problem step by step. End with the final answer on its own line in the form: #### <number>"; greedy decoding with at most 768 new tokens; the answer is graded against the reference answer: the first number after the last "####" if there is one, otherwise the last number in the response. Only weight values can change (same tensor names and shapes). A saved tensor is stored and evaluated in bfloat16 (round to nearest even), and load(name) returns that rounded value.

SCOPE. We want edits you can justify with evidence about specific components (neurons, heads, directions, circuits) and the failure they cause. Repairing a specific failure mechanism you find is in scope. Out of scope: the final norm and the embedding / output matrix (save_edit refuses them), multiplying a whole tensor by a constant (refused: save_edit refuses a change that is at least 99.5% aligned with the tensor itself, and a norm change that does nothing at run time), global changes to the output distribution.

METHOD.
1. Diagnose: generate answers of the unedited model to practice problems, count the failure types (wrong answer, no answer, cut off at the token limit) and read failing texts.
2. Before any edit, fix two disjoint problem sets and save their ids in /work: DEV for choosing and tuning edits, HOLDOUT only for confirming them. Never choose or tune on HOLDOUT.
3. Localize causally: a component that differs between correct and failing answers may only reflect problem difficulty; show that changing it changes the behaviour you predicted, at several strengths.
4. Measure with paired passes ("both") at full size: the budget counts passes, not their size, and a small pass gives a noisy measurement. The paired difference has a standard error of about 50/sqrt(n) points for n answers per model (answers drift apart once a token differs, so pairing helps less than one might expect). A teacher-forced pass costs one pass whether it reads 2 texts or {tf_texts:,}: use it at full size (for example the model's own correct and failing DEV answers, or all DEV reference solutions) to screen edits before spending generation passes. Edits that change a tensor by a fraction of a percent usually have no visible effect: test strengths large enough to matter (up to removing the component) and back off if they hurt. Judge edits by accuracy, not by fewer cut-offs or shorter answers.

RULES. Not allowed: autograd or optimisers of any kind (backward passes, torch.autograd, torch.optim, torch.func, functorch, jax); choosing weights as the minimiser of a loss over data samples, iteratively or in closed form (least squares, ridge, normal equations, the pseudo-inverse of an activation matrix, a regression or probe whose fitted weights are written into the model), however it is computed, summary statistics included; gradient-free search against a loss on data (finite differences, random or evolutionary search, scipy.optimize); computing a loss or score of candidate weights over stored per-sample activations in the kernel; running or simulating the network in the kernel instead of through the forward-pass tool; edits that encode practice problems or their answers; padding an edit with an unrelated change to get past a save_edit refusal; internet access. Allowed: statistics of the weights and of the activations the forward tool returned (means, differences, variances, norms, PCA/SVD, projections, correlations, top-k selections, attention patterns); hand-built edits from them (removing or reversing a direction in a matrix's output on chosen columns; rank-k additions made from statistics, including dividing a target vector by one neuron's mean activation, or by a head's mean output, so that a near-constant unit writes the target; zeroing, scaling or swapping rows, columns, heads or neurons); strengths, layers and column counts set by hand or chosen by comparing candidates with forward passes, each candidate costing passes from the budget; applying a candidate edit to a few summary vectors in the kernel to check what it does.
